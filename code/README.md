# Детекция препятствий по фронтальной камере: оптический поток против нейросетей

Код к дипломной работе. Два метода с одинаковым выходом (область препятствия,
сторона обхода, мера близости) сравниваются по времени обработки кадра и по
качеству на размеченных видео.

## Структура

```
code/
  common/          общая инфраструктура (не зависит от метода)
    types.py       Frame, ObstacleResult, BaseDetector
    sources.py     вебкамера, видео, папка кадров, TUM RGB-D
    decision.py    правило выбора стороны обхода (общее для методов и разметки)
    labels.py      формат разметки CSV
    metrics.py     precision/recall/F1, точность стороны, задержка, ошибка TTC, время
    viz.py         отрисовка результата
    tum.py         загрузка TUM RGB-D и авторазметка по глубине
  optical_flow/    метод 1: оптический поток
    backends.py    Farneback, DIS, Лукас-Канаде на сетке
    detector.py    дивергенция -> время до столкновения -> область
    synth_check.py проверка на синтетике с известным TTC
  neural_net/      метод 2: нейросети (следующий этап)
  methods.py       реестр методов: строка "flow:dis?preset=medium" -> детектор
  run_live.py      живая демонстрация на вебкамере
  run_bench.py     офлайн-сравнение на видео/датасете -> results/
  record.py        запись сырого видео с метками времени
  label_tool.py    ручная разметка видео
  tum_labels.py    авторазметка последовательности TUM по глубине
  plots.py         графики для диплома из results/
```

## Установка

```
py -3.14 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Все команды ниже запускаются из папки `code/` с активированным окружением.

## Рабочий цикл

1. Проверка на синтетике (не нужна камера):
   ```
   python optical_flow/synth_check.py
   ```
2. Живой запуск с вебкамерой, три варианта потока рядом:
   ```
   python run_live.py --methods flow:farneback flow:dis flow:lk --tile
   ```
3. Запись клипа для замеров (идти с ноутбуком на стену, коробку, человека):
   ```
   python record.py --out data/raw/wall_01.mp4
   ```
4. Разметка клипа вручную:
   ```
   python label_tool.py data/raw/wall_01.mp4
   ```
5. Замеры и метрики:
   ```
   python run_bench.py --source data/raw/wall_01.mp4 --methods flow:farneback flow:dis flow:lk
   python plots.py results/wall_01 --labels data/raw/wall_01.labels.csv
   ```
6. Датасет TUM RGB-D (скачать последовательность, например
   `rgbd_dataset_freiburg2_pioneer_slam`, распаковать в `data/tum/`):
   ```
   python tum_labels.py data/tum/rgbd_dataset_freiburg2_pioneer_slam
   python run_bench.py --source data/tum/rgbd_dataset_freiburg2_pioneer_slam --labels data/tum/rgbd_dataset_freiburg2_pioneer_slam/labels_ttc.csv
   ```
   Разметка создаёт labels_ttc.csv (для потока) и labels_dist.csv (для нейросети), пол исключается.


## Формат разметки

CSV `frame,present,side,dist_m,ttc_s`. `side` это рекомендуемый манёвр:
`left`, `right`, `stop` или `none`. `dist_m` и `ttc_s` заполняются только
там, где известны (TUM, синтетика).

## Метод по оптическому потоку, коротко

При сближении с поверхностью поле потока расходится из фокуса расширения,
и его дивергенция равна 2/TTC (TTC в кадрах). Поворот камеры и боковой сдвиг
дают почти однородное поле с нулевой дивергенцией, поэтому дивергенция
выделяет именно сближение. Детектор считает плотный поток, сглаживает его
нормированной свёрткой с весом по текстуре (в плоских участках поток не
определён, и без взвешивания на границах плоских пятен возникает ложная
дивергенция), берёт дивергенцию, усредняет по сетке ячеек 20x15, сглаживает
во времени и выделяет связную область ячеек, где TTC меньше порога.
Настройки в `optical_flow/detector.py`, класс `FlowConfig`.

Параметры по умолчанию и что они дают (подобраны на синтетике):

| параметр | значение | смысл |
|---|---|---|
| `work_width` | 320 | рабочее разрешение; время растёт ~квадратично |
| `ttc_threshold_s` | 4.0 | порог времени до столкновения |
| `flow_sigma` | 5.0 | сглаживание поля перед дифференцированием, px |
| `min_texture` | 2.5 | масштаб веса достоверности по градиенту яркости |
| `min_conf` | 0.2 | ячейки с меньшей достоверностью не голосуют |
| `min_cells` | 4 | минимальная область, ячеек |
| `min_persist` | 1 | сколько кадров подряд держать область; 2 даёт +3..4% точности на стене и ~0.3 с задержки |
| `ema_alpha` | 0.4 | сглаживание дивергенции во времени |
| `min_global_mag` | 0.1 | ниже этого среднего потока камера считается неподвижной |
| `corridor_frac` | 0.6 | препятствие ищется только в центральной зоне кадра (путь камеры); периферия даёт дивергенцию от стен сбоку |
| `ground_frac` | 0.2 | нижняя часть кадра не голосует: пол/земля сближается, но не препятствие |
| `derotate` | True | из дивергенции вычитается наклонная плоскость, это компенсация поворота камеры |
| `frame_step` | 1 | поток между кадром k и k-N; на TUM не помог |
| `max_dt` | 0.15 | пропуски кадров длиннее этого сбрасывают состояние |

Бэкенды: `flow:farneback` (~24 мс на кадр при 320 px), `flow:dis` (пресет
medium, ~10 мс; `flow:dis?preset=fast` ~7 мс, но теряет мелкие объекты),
`flow:lk` (Лукас-Канаде на сетке 16 px, ~6 мс; `flow:lk?cell=12` плотнее).
Замеры на Ryzen 5 7535HS.

Ограничение метода: он видит только сближение. Неподвижная камера или
движение вдоль препятствия не дают дивергенции, а сплошная бестекстурная
стена не даёт потока вовсе. Это ожидаемое место, где нейросетевая оценка
глубины должна выиграть.
